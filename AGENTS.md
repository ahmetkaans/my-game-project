# AGENTS.md

Before doing anything with the game files (`game/index.html` and the files next to it), read the "File map" at the top of README.md first, then read in full the README.md and DESIGN.md sections it points to for your task (always the map; before you change something, also README "Confirmed decisions" and the matching "Change together" row of the map; for a plain question about how things work you may skip those two). When unsure, read more, not less. When it is needed and logical to edit README.md and DESIGN.md files, you can. README.md file should be filled with important details, the algorithms, anything you will need for the changes in the game files to guide you in the future. DESIGN.md file should be filled with important details about the design process and design language and style. Don't change AGENTS.md unless asked.

## Rules

1. **Ask first.** Before writing code for a new feature or change, ask the owner about every important decision and wait for the answers.
2. **Plain files, no build step.** The game is plain files in `game/`: `index.html`, `css/`, `js/` and `data/`. No build step, no tools that must run before the game opens, no audio or image files. It must open by double-click from the folder, offline. The only external resource is the Inter font from Google Fonts. File names are lowercase. Private material lives only in `.gitignore/`.
3. **Placeholder content.** Any text the owner has not explicitly named stays lorem ipsum. The list of names fixed by the owner is in DESIGN.md.
4. **Don't decide open questions.** Do not invent rules for things that are still undecided (for example, the spelling rule for very short answers or the grammar content method). Follow the notes in README.md ("Open questions" and the Roadmap's open questions) and ask the owner.
5. **Numbers live in `CONFIG`.** Change times, points, thresholds and similar values only in the `CONFIG` object, and update the Configuration table in README.md whenever `CONFIG` changes.
6. **Test before handing over:**
   - no errors in the browser console;
   - works at phone width;
   - check both light and dark mode;
   - works with "reduce motion" turned on;
   - test remembered settings (language, theme, sound, same duration, SmartBoard mode) in a normal browser, because previews served as `data:` URLs block `localStorage`.
7. **Git.** Commit only when asked, with a meaningful message. Do not push unless asked. **Every commit adds an entry to `CHANGELOG.md`** (see README.md, "Changelog").
8. **Private `.gitignore/` folder.** The files in the `.gitignore/` folder must never be uploaded to GitHub: never `git add`, commit or push them. The folder is excluded locally through `.git/info/exclude` (a folder named `.gitignore` cannot work as an ignore file). It has five drawers: `tools/` (check scripts, test server, play-through test), `drafts/` (drafts and plans in progress), `words/` (word lists), `plans/` (theme plans) and `archive/` (the old single-file version of the game, kept just in case: never changed, never needed for a task). For A1 work, read `words/ORG_A1_WORDS.md`. `words/A1_WORDS.md` should be read only when you work on creating a file in the same format as `ORG_A1_WORDS.md` (for example for another level), just to understand how the original word file is turned into a useful file for AI, or when the owner asks you to.
9. **Draft, validate, review, then write.** Don't add questions (or explanations, glossary meanings or target-word plans) to the files right after you write them. Write the draft in a draft file in `.gitignore/drafts/`, run the check script on it (README.md, "Check script") and fix what it reports. Show the owner a readable draft and remind the owner to ask you to review it against the "Review checklist" in README.md. The review is done by reading, item by item, with a quote as evidence for every hard item; a script result is evidence, never approval. Change the files only after that review and the owner's go-ahead. The steps are in README.md, "Workflow: draft → review → write".
10. **Check for inconsistencies first.** Before doing anything the owner asks, check whether something stands in its way or doesn't fit together: two rules that contradict each other, a rule that contradicts the request, docs that don't match the code (or the code and `CONFIG`), or anything else that is inconsistent (for example a target-word plan and its questions, or DESIGN.md and the page). If you find something, tell the owner what it is and where, suggest a fix, and wait for the answer before you continue.
11. **Change a rule everywhere.** When you change a rule, a decision, a name, a number or any other fact, find every place it appears and change it in all of them: AGENTS.md, README.md (including its file map), DESIGN.md, the game files (`game/index.html`, the css files in `game/css/`, the code in `game/js/` and the data in `game/data/`: code, `CONFIG`, comments, texts, styles, questions), the check script, the private files in `.gitignore/` (organized word files, plans; never `A1_WORDS.md` or another original word list, which are never changed) and your memory notes. Search for it (for example with grep) instead of relying on memory, because some rules are written in several sections of README.md. Then tell the owner which places you changed.
12. **Keep the file map true.** The "File map" in README.md must always match the files. In the same change, update it whenever you add, remove, rename or move a section banner, function, HTML id, data file, code file, CSS section anchor, doc heading or file that the map lists, or change what it says lives where. Then run `powershell -ExecutionPolicy Bypass -File .gitignore/tools/check_filemap.ps1`; it must say OK before you hand over. If the map and the files disagree, fix the one that is wrong and tell the owner (rule 10).
13. **Keep the question check script and its guide true.** When you add, change or remove a check, an option, a number or a file format the script depends on, update in the same change: the script's header, the guide in README.md ("Check script"), the list the script prints with `-Checks`, the self-test cases, and every place that quotes the expected result. Run the self-tests and compare the real bank's report before and after: it must stay the same unless the change is meant to change it, and then tell the owner what changed. Never weaken a check to make a question pass.
